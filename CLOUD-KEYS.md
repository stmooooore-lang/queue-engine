# Ключи облака — единый документ

**Обновлено 2026-08-30 — предыдущая версия (2026-08-22) устарела: тогда
был заведён только NVIDIA, к сегодняшнему дню добавились ещё три ключа, и
рекомендация "заводить отдельные аккаунты под облако" ниже была не
выполнена для них.** Один документ на всё облако. Здесь только то, что
нужно облачным прогонам: какие секреты, откуда берутся, что ломается без
них.

## Как облако получает модели

Раннер **не достаёт** до прокси на Маке и никогда не достанет. Поэтому
`cloud-agent.yml` поднимает LiteLLM внутри задания из `cloud-config.yaml` —
семь ролей, 23 развёртывания, та же карта, что локально. Ключей в файле нет:
каждый заменён на `os.environ/<ПРОВАЙДЕР>_API_KEY`, значения приходят из
секретов репозитория.

Расчёты — корридорный замер, бисекция — **моделей не трогают вообще** и
работают без единого ключа.

2026-08-30:

| Секрет | Роли, которые от него зависят | Есть | Тот же ключ, что на Маке? |
| --- | --- | --- | --- |
| `NVIDIA_API_KEY` | act, architect, judge, coder | **да** | **да** |
| `GEMINI_API_KEY` | gemini | **да** (добавлен 2026-08-22) | **да** |
| `GROQ_API_KEY` | coder, cheap | **да** (добавлен 2026-08-22) | **да** |
| `MISTRAL_API_KEY` | plan, coder | **да** (добавлен 2026-08-22) | **да** |
| `VERTEX_PROJECT` / `VERTEX_CREDENTIALS_JSON` | judge (vertex_ai) | **нет** — `cloud-agent.yml` их упоминает, но ни один секрет не заведён | — |
| `OPENROUTER_API_KEY` | — | не нужен | — |
| `PLEXUS_CRYPTOCOMPARE_KEY` | — | больше не используется, маршрут перешёл на статический архив | — |

**Важное следствие для устранения проблем — касается конкретно GitHub
Actions секретов, не Render (см. ниже, там Gemini/Groq отдельные):** раз
все четыре реальных ключа в этом репозитории общие с локальным стеком,
разовый прогон `cloud-agent.yml` и локальная очередь (`queue.sh` на Маке)
делят одну и ту же ёмкость по всем четырём провайдерам одновременно, не
только по NVIDIA. Замедление или `RateLimitError` в одном может быть
вызвано нагрузкой из другого — это подтверждено 2026-08-29/30 (см.
`docs/DECISIONS.md` в проекте среды, падения `plexus-cheap`/`plexus-coder`
во время облачных прогонов совпали по времени с активной локальной
очередью). **Постоянный прод на Render этой проблемой не страдает** —
у него отдельная ёмкость по Gemini/Groq.

Провайдер без секрета даёт лань, которая падает и уходит в фолбэк. Прогон от
этого не встаёт, но роль работает хуже, чем на Маке.

**ОБНОВЛЕНО 2026-08-30, вечер того же дня: Vertex решили пустить в облако
намеренно** (GitHub-прогон запускается только вручную с терминала, не с
телефона — риск ниже, чем у постоянного VM/Telegram-пути).
`make-cloud-config.py` больше не содержит `vertex_ai` в `SKIP_PROVIDERS` —
теперь он идёт через `os.environ/VERTEX_PROJECT` и
`os.environ/VERTEX_CREDENTIALS_JSON`, как любой другой провайдер.
`cloud-config.yaml` перегенерирован и содержит vertex_ai-развёртывания
для `plexus-judge` и `plexus-pro`.

**В GitHub Actions секретах этого репозитория `VERTEX_PROJECT`/
`VERTEX_CREDENTIALS_JSON` по-прежнему не заведены** (проверено
`gh secret list`) — там лейн просто упадёт в фолбэк, пока/если их не
добавят. **Но на Render (см. следующий раздел) они уже есть** — значит на
постоянном проде Vertex должен реально заработать после ближайшего
редеплоя, без дополнительных действий.

**Срок этого решения не бессрочный: кредит Vertex истекает 2026-11-17
(EUR 263, `plexus-pro`/`plexus-judge`).** План на этот случай уже принят,
не открытый риск: разовая оплата OpenRouter ($10) поднимает его дневной
лимит с 50 до 1000 и делает `plexus-reserve` (OpenRouter) реальной заменой
роли резерва вместо Vertex. Решение об этом платеже — по сроку 2026-11-17,
см. `docs/DECISIONS.md` в проекте среды.

## Render — отдельное хранилище секретов, не то же самое, что GitHub

Render (постоянный LiteLLM-прокси, к которому реально ходит VM/Telegram-
бот) хранит свои переменные окружения отдельно от секретов GitHub Actions
— проверено визуально владельцем в Render Dashboard → сервис
`render-service` → Environment, 2026-08-30:

| Секрет | Есть на Render | Тот же ключ, что на Маке? |
| --- | --- | --- |
| `GEMINI_API_KEY` | да | **нет** — отдельный, помеченный `(render-plexus)` в `keys.txt` (по памяти владельца, не сверено побайтово) |
| `GROQ_API_KEY` | да | **нет** — отдельный, `(render-plexus)` (аналогично) |
| `MISTRAL_API_KEY` | да | не проверено в этом заходе |
| `NVIDIA_API_KEY` | да | предполагается общий — "делить нечего", как и везде |
| `LITELLM_MASTER_KEY` | да | свой, не пересекается по конструкции |
| `OPENROUTER_API_KEY` | да | не используется (`make-cloud-config.py` его всё ещё пропускает) |
| `VERTEX_PROJECT` / `VERTEX_CREDENTIALS_JSON` | **да, уже настроены** | — |

**Это значит целевая архитектура (Mac+GitHub общие ключи, VM/Render —
свои) для Gemini/Groq на Render уже выполнена** — расхождение,
описанное в разделе ниже как "рекомендация не выполнена", относится
только к секретам **GitHub Actions**, не к Render. Не путать два разных
хранилища при следующей ревизии.

## Откуда брать ключи для облака — историческая рекомендация, не выполненная

Ниже — то, что было решено 2026-08-22 и не сделано для трёх из четырёх
провайдеров. Оставлено как есть, не переписано задним числом, чтобы было
видно расхождение между решением и практикой, а не чтобы выглядело, будто
так и планировалось.

**Не копировать локальные — так гласила рекомендация.** Квоты считаются по
проекту, а не по месту вызова: один и тот же ключ, вызванный из раннера и с
Мака, тянет один потолок, и два прокси друг о друге не знают — счётчики
живут в памяти процесса. Копия даёт не вторую ёмкость, а двух оптимистов на
одной квоте — именно это и происходит сейчас для Gemini/Groq/Mistral.

| Провайдер | Рекомендация 2026-08-22 | Реальность 2026-08-30 |
| --- | --- | --- |
| Google (Gemini) | отдельный проект в AI Studio, ключ оттуда | тот же ключ, что на Маке |
| Mistral | отдельный workspace, ключ оттуда | тот же ключ, что на Маке |
| Groq | отдельный аккаунт | тот же ключ, что на Маке |
| NVIDIA | ничего заводить не нужно — нет дневного потолка, делить нечего | тот же ключ, что на Маке (это и планировалось) |

Подробности и цитаты — `docs/PROVIDER-ISOLATION.md` в проекте среды.

## Как класть

Settings → Secrets and variables → Actions → New repository secret. Значение
вводится в браузере и после сохранения не показывается никому, включая
владельца.

Проверить, что облако видит роли: Actions → `cloud-agent` → Run workflow. Шаг
«proxy with the real lanes» печатает список ролей, которые поднялись.
