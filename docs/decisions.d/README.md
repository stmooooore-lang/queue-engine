# docs/decisions.d/ — куда писать инфраструктурные аудиты (контур queue-engine)

Создано 2026-11-09 вместе с правилом `[NO-ARTIFACT]` (см. `AGENTS.md`, раздел
5, и `AGENTS.md` родительского репозитория, раздел `No Artifact Tasks`).

**Зачем.** До артефакт-гварда (`9ed16b6`) пустое рабочее дерево означало
`готова`: 7 из 14 прогонов 2026-11-08 (задачи 160, 162, 166, 167, 168, 171,
173) закрылись без единого коммита, а их результаты «лежали» там, где
проверяющий их не находит: `notes/` и в тексте `result`, не в репозитории.
Теперь задача без артефакта может быть `готова` только с маркером
`[NO-ARTIFACT]`, и маркер требует отчёта — иначе дерево пусто и задача
провалена.

**Что здесь лежит.** Аудиты инфраструктурного контура `queue-engine`:
проверка фактов по коду, логам и прогонам, к которым нет файла-артефакта.
Именовать файлы по дате и предмету: `YYYY-MM-DD-<subject>.md`.

**Какие требования.** Сначала факт из репозитория (файлы, строки, ссылки),
потом вывод. Файл без доказательств — не аудит, а заголовок, и засчитан
не будет.

**Куда НЕ писать:** `notes/` — черновики; аудит в `notes/` считается
несуществующим. Отчёты задач продукта Plexus (WORKDIR = `plexus-doc`) идут в
`canon/content/`, не сюда.
