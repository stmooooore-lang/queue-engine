# Бриф: сборка render-service падает на установке LiteLLM

Написано 2026-08-23 экспертом. **Это бриф, не задача** — файл задачи с
адресами и приёмочной командой пишет агент, по правилу
`docs/RULE-LEVELS.md` уровня 3.

## Что наблюдается

Владелец создал Web Service на Render по инструкции `render-service/README.md`
и сборка не прошла. В журнале: что-то про версию Python и «не найдено»,
затем провал сборки.

## Что установлено, а не предположено

Проверено по документации Render (`render.com/docs/native-runtimes`):

- у Node-рантайма Render **есть** `python3-pip` в наборе инструментов сборки —
  то есть Python там в принципе присутствует, дело не в его отсутствии;
- **но рантайм у сервиса ровно один.** Node и Python как два основных
  рантайма одновременно не поддерживаются: «You set your service's runtime
  while creating your service»;
- для случая, когда нужны оба языка, Render **прямо рекомендует Docker** —
  «You want full control over which tools and libraries are present (and
  absent) in your runtime environment».

Наша сборка требует именно оба: `pip install "litellm[proxy]==1.83.9"` для
прокси и `npm install && npm i -g cline` для агента.

## Две гипотезы о конкретной ошибке, обе непроверенные

Названы, чтобы агент проверил их первым делом по журналу сборки, а не начинал
с переписывания:

1. **`pip` против `pip3`.** В Debian 12 команда называется `pip3`; голый `pip`
   может отсутствовать — это дало бы ровно «не найдено».
2. **PEP 668.** Debian 12 помечает системный Python как
   externally-managed, и `pip install` без `--break-system-packages` или без
   venv отказывается ставить пакет — это дало бы сообщение, в котором
   упоминается версия и окружение Python.

## Что нужно сделать

Починить сборку так, чтобы сервис поднимался на бесплатном тарифе Render.
Способ выбирает агент, но два ограничения жёсткие:

- **версию LiteLLM `1.83.9` не менять.** Более новая не стартует вовсе:
  `proxy_cli.py` делает голый `from proxy_server import`, который
  резолвится только когда каталог пакета оказался в путях поиска. Проверено
  на раннере GitHub, прогон 32549839784;
- **и прокси, и Cline должны быть доступны в рантайме**, а не только во время
  сборки. Глобальная установка npm на этапе сборки может не пережить переход
  к запуску — это проверяется, а не предполагается.

Docker — вероятно правильный путь, раз Render сам его рекомендует для двух
языков. Но если найдётся способ проще и он работает, он лучше.

## Приёмка

Её пишет агент, но она обязана проверять **поведение, а не наличие файлов**:
сервис поднялся, `GET /` отвечает, `GET /test` возвращает JSON с полем
`answer`, в котором осмысленный ответ модели. Проверка «Dockerfile существует»
приёмкой не является.

## Чего в задаче нет

Переезда очереди и воркера на Render. Здесь только один вопрос: **тянет ли
бесплатный тариф связку LiteLLM + Cline в одном живом процессе.** Ответ на
него решает, строить ли на Render дальше.
